# 07. KFP · 피처 조회부터 배치 추론까지 연결하기

**CH5 · Kubeflow Pipelines.** 앞에서 준비한 피처와 등록 모델을 반복 실행 가능한 작업으로 묶는다. 이 장의 실행 대상은 Kubernetes의 컴포넌트 Pod이며, 아래 DAG는 연결 설계다.

## 1. 노트북과 파이프라인의 차이

노트북은 같은 메모리에 남은 변수나 실행 순서에 의존하기 쉽다. KFP에서는 각 컴포넌트의 입력·출력·이미지·의존성을 명시한다. 별도 Pod에서 실행되므로 이전 셀의 DataFrame을 직접 이어받지 않는다. 반복 실행과 실패 위치 확인에 필요한 경계를 만드는 과정이다.

![KFP 네 단계와 파라미터·Dataset 전달](/images/week02-kfp.svg)

| 개념 | 의미 | 예시 |
|---|---|---|
| Component | 독립적으로 실행하는 작업 정의 | 피처 조회·모델 추론 |
| Pipeline / DAG | 작업과 의존 관계 | 입력 확인 후 피처 조회 |
| Parameter | 직렬화 가능한 작은 값 | model_uri·데이터 해시·시간 구간 |
| Artifact | 파일 형태의 큰 산출물과 메타데이터 | Input/Output Dataset |
| Run | 파이프라인 한 번의 실행 | 파라미터·단계별 상태·로그 |
| Cache | 조건이 맞을 때 이전 산출물 재사용 | 동일 입력 작업의 재실행 절감 |

`Input[Dataset]`·`Output[Dataset]`은 전달 형식이다. CSV/Parquet 컬럼과 자료형의 정확성은 코드에서 검사한다. 큰 DataFrame을 문자열 파라미터로 넘기지 않고, 출력 경로에 파일을 기록해 다음 작업이 읽게 한다.

## 2. 제조 품질 배치 추론의 네 단계

| 단계 | 입력 | 처리·출력 | 실패 기준 |
|---|---|---|---|
| 1. 입력 확인 | Entity·예측 시각 표, 계약, 해시 | 검증된 요청 Dataset | 해시 불일치·필수 컬럼 누락 |
| 2. 피처 조회 | 요청 Dataset, 피처 정의 | Historical 피처 Dataset | 미래 값·키 중복·금지된 결측 |
| 3. 모델 추론 | 피처 Dataset, 고정 model_uri | 식별자를 보존한 예측 Dataset | 스키마 불일치·모델 로드 실패 |
| 4. 결과 저장 | 예측 Dataset, 실행 정보 | 결과 파일·검증 요약 | 행 수·키·예측값 검사 실패 |

모델 선택은 앞선 MLflow 학습에서 끝났다. 배치 추론마다 모델을 다시 학습하거나 임의의 최신 버전을 고르지 않는다. `selection.json`의 구체적 버전 URI를 사용해 실행 간 모델 변경을 통제한다.

## 3. 컴파일·등록·실행·확인은 서로 다른 단계

파이썬 SDK로 파이프라인을 정의하고 YAML로 컴파일한다. KFP에 업로드한 뒤 파라미터를 지정해 Run을 만든다. **컴파일 성공은 클러스터 실행 성공을 의미하지 않는다.** 이미지 접근·스토리지·서비스 주소·권한은 실행 환경에서 확인해야 한다.

작업 Pod의 이미지에는 필요한 MLflow·Feast·모델 런타임 패키지를 포함하고 버전을 기록한다. 파이프라인 제어용 Pod와 실제 컴포넌트 Pod의 로그를 구분한다. 재시도 정책은 일시적 연결 실패에 유용하지만 잘못된 피처 계약을 반복 실행해서 해결하지는 못한다.

캐시를 켜면 서버 뒤에서 데이터가 바뀌어도 입력 파라미터가 같아 이전 결과를 사용할 수 있다. 데이터 스냅샷·해시와 피처 정의 버전을 입력에 포함하고, 최초 연결 검증에서는 캐시를 끄거나 캐시 사용 여부를 명시해 실제 실행을 구분한다.

## 4. Kubernetes 서비스와 저장소 연결

MLflow는 `mlflow.week02.svc.cluster.local:5000`처럼 컴포넌트 실행 위치에서 접근 가능한 주소를 쓴다. 모델은 서버 API·아티팩트 경로로 로드하고, 원본·중간 Dataset·최종 결과는 KFP가 접근할 수 있는 저장소로 연결한다. 개인 PC의 파일 경로나 다른 namespace의 PVC를 자동 공유한다고 가정하지 않는다.

| 연결 | 실행 전 확인 |
|---|---|
| 컴포넌트 → MLflow | 고정 모델 버전 조회·아티팩트 다운로드 |
| 컴포넌트 → Feast | Registry·Offline 소스 접근과 시점 조회 |
| 컴포넌트 → 결과 저장소 | 지정 경로 쓰기·재조회·내용 읽기 |
| 단계 사이 | Dataset 파일 생성과 다음 단계의 읽기 |

저장소 접근 정보는 클러스터 Secret과 환경 설정으로 주입한다. 문서나 캡처에는 인증값을 넣지 않는다. 학습용 단일 노드 환경에서도 작업 간 입력·출력 경로를 명확히 해두면 이후 저장소를 교체할 때 추론 코드를 덜 바꿀 수 있다.

::: tip 실습 화면 ③ · KFP 실행과 산출물
실행 후 **네 단계가 보이는 Run DAG**, 단계별 성공 상태, 마지막 단계의 **결과 파일 경로·행 수·컬럼 검사 요약**을 캡처한다. 화면의 성공 표시와 실제 파일 내용 확인을 함께 남긴다. 캡처 후 이 안내를 실제 화면과 짧은 해석으로 교체한다.
:::

## 5. 다음 단계는 결과 파일 검증

모든 단계가 성공했어도 결과가 빈 파일이거나 Entity가 사라지면 업무에서 사용할 수 없다. [결과 검증](/ml-platform/week02-verification)에서 고정 입력·모델·피처를 기준으로 재현성과 추적성을 확인한다.
